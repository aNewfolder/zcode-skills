# CC98 校外查看工具（WebVPN 版）

和 `cc98-crawler` 共用**同一个本地应用**（http://127.0.0.1:8765，应用目录可用环境变量 `CC98_APP_DIR` 指定），
但本 skill 解决的是**没有校园网**的场景。应用会自动选择通道：
校内直连 → WebVPN 反代 → 本地代理，页面顶部徽章实时显示当前通道。

- 辅助脚本：`~/.agents/skills/cc98-crawler/scripts/cc98.py`（零依赖，**需与 cc98-crawler skill 一起安装**，两 skill 共用）
- 输出位置、下载结构、限速机制与 cc98-crawler 完全一致

## 红线（先读）

- **只读**：绝不回帖、发帖、点赞、签到，绝不调用任何写接口。
- **限速内置不可调低**：所有 CC98 请求默认间隔 3 秒带抖动；实时轮询每轮固定 ≤5 个请求、
  间隔下限 5 分钟。不要连续 `live --refresh`（缓存期内无意义）。
- **WebVPN 是学校的账号**：登录、掉线重登都要节制；程序化登录失败 2 次就停，让用户走浏览器。
- 出现"疑似被限流"：立即停手，让用户把间隔调大到 5~10 秒，等几小时再试。

## 与校内版的两个本质差异（已由应用解决，向用户解释时用）

1. CC98 域名在校外解析到内网地址 `10.10.98.98`，**直连物理不可达**——不是 bug，
   所以必须走 WebVPN（`webvpn.zju.edu.cn` 反代）或本地代理（zju-connect / RVPN）。
2. CC98 **匿名读不了帖子**（API 返回 401），只能看热帖标题列表。因此"完全不登录"做不到：
   最小方案 = WebVPN 用浙大上网账号（学校账号，不是 CC98 账号）+ CC98 token 只读使用。

## 标准流程

### 0. 确认服务和通道

```
python ~/.agents/skills/cc98-crawler/scripts/cc98.py net-status
```

- "接入方式：校网直连" → 在校内，任何命令直接用（和 cc98-crawler 一样）。
- "接入方式：WebVPN" → 已就绪，直接往下走。
- "不可用 / blocked" → 让用户在网页 http://127.0.0.1:8765 的「设置 → 网络接入」里：
  1) 输入**浙大上网账号**（学号+密码）点「登录 WebVPN」；遇验证码/二次验证时，改在浏览器登录
     webvpn.zju.edu.cn 后把 `wengine_vpn_ticket…` cookie 粘贴进兜底框；
  2) 或者自己跑 zju-connect/RVPN，把代理地址（如 `socks5://127.0.0.1:2345`）填入并保存。
  **不要替用户输入任何密码。**
- 报"CC98 应用未启动" → `cd` 到应用目录后台跑 `python app.py`，等 3 秒重试。

### 1. 实时动态（本 skill 的核心）

```
python "<cc98.py 路径>" live --limit 25        # 读本地快照，秒回，零请求
python "<cc98.py 路径>" live --refresh         # 真实跑一轮（≤5 个请求，约 15~40 秒）
```

- 每条带来源标签：`hot_daily`（每日热帖）/ `hot_week`（每周热帖）/ `board:版面名`（关注版面）。
- 关注哪些版面复用推送偏好：`python "<cc98.py>" prefs add board 版面名`，实时轮询取前 3 个。
- 新帖标 🆕（本轮新出现）；页面端还有 SSE 实时推送和"下轮倒计时"。

### 2. 页内阅读（不抓文件、只想看帖时用）

```
python "<cc98.py 路径>" read 6631929 --pages 2        # 拉前 40 楼正文
python "<cc98.py 路径>" read 6631929 --pages 5 --max-len 0   # 更多楼层、不截断
```

- 真实请求且已限速（1 次详情 + 每页 20 楼 1 个请求），服务端有 10 分钟缓存，重复读不重复耗请求。
- 网页端点帖子标题打开阅读器更舒服（Markdown 渲染、继续加载、WebVPN 模式下图片也走代理）。

### 3. 搜索 / 抓取 / 推荐

命令与 cc98-crawler 完全一致（`search` / `crawl` / `feed` / `prefs` / `history`），
走的就是当前通道，无需任何额外操作。校外场景下搜索抓取会稍慢（经 WebVPN 转发），属正常。

### 4. 通道出问题时的排查顺序

```
python "<cc98.py 路径>" net-status        # 看哪个环节断了
# 网页「设置 → 网络接入 → 网络自检」：一键探测直连/WebVPN/白名单/CC98 API（≤2 个真实请求）
```

| 现象 | 处理 |
|---|---|
| WebVPN 登录返回"验证码/二次认证" | 用浏览器登录后粘贴 cookie 兜底；或等一会再试 |
| WebVPN 已登录但自检显示 CC98 API 不通 | 可能学校白名单调整；换 zju-connect 代理方案 |
| "WebVPN 会话过期"反复出现 | 页面勾选"记住"让它自动重登；仍频繁掉线属学校会话策略，正常 |
| api 报 cannot_entry_board / 401 | CC98 未登录，让用户在页面登录 CC98 账号（匿名读不了帖） |
| 一切正常但帖子图片不显示 | WebVPN 模式下附件/图片需要登录态，文字不受影响；重要文件用 crawl 下载 |

## 交付

把 `live` 列表或 `read` 的正文摘要给用户；用户要文件时走 `crawl`，输出结构同 cc98-crawler。
